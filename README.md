### Blog — Medium Auto-Sync

Articles are automatically fetched from Medium every 6 hours via GitHub Actions.

**How it works:**
1. `fetch-medium.js` reads `https://medium.com/feed/@ferhattufekci`
2. Category is detected automatically from RSS tags (`systems` / `test` / `software`)
3. Existing article language metadata is preferred; otherwise `js/medium-language.js` scores Turkish/English vocabulary in the title and content. The sync script, browser fallback, badges and language filter share this resolver.
4. Articles are saved to `data/medium-*.json`
5. Browser reads these JSON files — no CORS issues

Card excerpts use the RSS `description` when present, otherwise the first non-empty introductory paragraph in `content:encoded`. HTML entities are decoded and Medium's continuation footer is removed; the selected preview is shown in full without character or line limits. This does not read a separate Medium SEO description/subtitle field or put the full article body in the card. Existing ellipses in cached/source text remain until the next successful RSS sync supplies a fuller preview.

**To exclude an article from the site:**  
Add its hex ID (last segment of the Medium URL) to the `EXCLUDE` array in `scripts/fetch-medium.js`.

**No manual steps needed when publishing a new article on Medium.**

### Projects — GitHub Auto-Sync

Repositories are automatically fetched from GitHub every Monday via GitHub Actions.

**How it works:**
1. `fetch-github.js` calls `GET /users/ferhattufekci/repos` (REST API)
2. Pinned repos are fetched via GitHub GraphQL API
3. All languages per repo are fetched via `GET /repos/{owner}/{repo}/languages`
4. Starred repos are fetched via `GET /users/ferhattufekci/starred`
5. Category is detected automatically from repo name, description, and topics
6. Results are saved to `data/github-repos.json`, `data/github-starred.json`, `data/github-meta.json`

**Projects page sections:**

| Section | Description |
|---|---|
| 📌 PINNED | Repos pinned on GitHub profile |
| 📂 ALL REPOSITORIES | All public repos, sorted by stars |
| ⭐ STARRED | Repos starred by Ferhat — resources he finds valuable (first 20 shown, expandable) |

**Category filter applies to PINNED and ALL REPOSITORIES sections.**  
**Label updates dynamically to show the selected filter name.**

**To exclude a repo from the site:**  
Add the repo name to the `EXCLUDE` set in `scripts/fetch-github.js`.

**No manual steps needed when creating or updating a repository.**

### SEO / AI Discoverability (GEO & AEO)

The Blog and Projects sections use client-side `fetch()`. Raw HTML fallbacks and static Markdown also make their summaries readable to clients that do not execute JavaScript. These files support discovery; they do not guarantee indexing or inclusion in an AI answer.

| What | Where | Purpose |
|---|---|---|
| `<noscript>` fallback | `index.html`, inside the Projects and Blog subpages | Real titles/links/descriptions in the raw HTML for crawlers that don't execute JavaScript. Invisible to normal browsers with JS enabled — no visual or duplicate-content impact. |
| `llms.txt` | site root | Plain-text index (the emerging `llms.txt` convention) summarizing who this site is about, its core pages, and current articles/projects — meant to be fetched directly by LLM-based answer engines. |
| `scripts/build-static-seo.js` and `scripts/build-agent-content.mjs` | `scripts/` | Regenerate fallback HTML, llms.txt, Markdown and the sitemap from source content; unchanged files are not rewritten. |
| `Person.knowsAbout` | JSON-LD in `index.html` `<head>` | Topical signals for search/AI, drawn from the existing `<meta name="keywords">` list. |
| AI crawler allowlist | `robots.txt` | Explicitly lists GPTBot, ClaudeBot, PerplexityBot, Google-Extended, and others. Behavior is unchanged (the wildcard `Allow: /` already covered them) — this documents the opt-in. |

`build-static-seo.js` runs automatically as a step in both `fetch-github.yml` and `fetch-medium.yml`, right after the data fetch, so the fallback content and `llms.txt` stay in sync with real data on every scheduled sync. It's idempotent — re-running it with unchanged data produces no diff, so it never creates empty commits.

**To regenerate manually:**
```bash
node scripts/build-static-seo.js
```

### Agent readiness and verification

The site is published at `https://ferhattufekci.github.io` on GitHub Pages. Pages uses `build_type=workflow`: `pages.yml` → shared quality job → `.pages-site` artifact containing only public files → deployment → live GET verification. `.nojekyll` is retained. Node is used only for generation and testing. A failed quality job blocks deployment; data commits made with GITHUB_TOKEN are tested through `workflow_run`.

| Source | Producer / consumer |
| --- | --- |
| Medium RSS / GitHub API | `scripts/fetch-medium.js`, `scripts/fetch-github.js` → `data/*.json`; the browser's Blog/Projects sections and generators read these snapshots |
| `data/github-repos.json`, `data/medium-all.json` | `build-static-seo.js` → marked noscript sections in `index.html` and lists in `llms.txt` |
| `index.html`, `content/trust-pages.json`, `js/theme-init.js`, `js/error-card.js` | `build-agent-content.mjs` → `index.md`, trust-page HTML/Markdown, `404.html`, `404.md`, `sitemap.xml` |
| `llms.txt`, `agent-instructions.md` | Manually maintained usage guidance; marked lists in llms.txt are generated automatically |

Update the source rather than editing a generated file alone, then run `npm run generate`. The Person description and static contact links live in `index.html`. Trust-page content comes from `content/trust-pages.json`; the privacy text describes the existing Analytics, AdSense, Calendly and browser storage usage. Provider and consent-management settings are the site owner's responsibility.

**Platform limits:** GitHub Pages does not run application code that changes a URL's body and Content-Type based on Accept; it also [does not support custom MIME configuration](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site#mime-types-on-github-pages). `/index.md` is a useful alternative representation, not Markdown negotiation on the homepage. `/404.html` provides explanatory HTML and a real 404 for missing root and nested paths; it does not provide a Markdown error response. Since fragments are not sent to the server, `/#resumes` shows a client-side 404 view within an HTTP 200 document. The MIME type of `.md` files is measured from live responses.

**Shared 404 and controls:** `js/error-card.js` owns the heading, message and recovery destinations for both error views. The generator extracts the sidebar, mobile header and navigation from `index.html` through `scripts/lib/not-found-document.mjs`; `js/site-shell.js` handles the shared drawer and measured header height without SPA/plugin dependencies. Static 404 links and assets are root-absolute. There is no redirect: missing paths retain HTTP 404 and `noindex`; invalid fragments retain HTTP 200. About/Contact/Privacy keep their simple document layout. Both recovery links reuse the unchanged About Me Resume CTA.

Theme and menu controls share `.icon-btn`: hover is limited to fine pointers with hover support, pressed feedback ends on release, and keyboard focus uses `:focus-visible`. Closing by Escape/keyboard restores drawer focus; pointer closes do not steal it. Reduced motion disables icon rotation/scaling. The neutral base margin also keeps trust-page theme controls aligned.

**Trust-page navigation:** About, Contact and Privacy remain indexable, linked in the sitemap/agent guide, and available through the footer. Their header contains only “← Back to portfolio” (`/`, opening About Me) and a right-aligned theme toggle. The footer marks the current page as non-clickable text with `aria-current="page"`; its link list lives in `scripts/lib/agent-documents.mjs`. Both header targets are at least 44px tall. Navigation is excluded from Markdown, so this layout does not change the trust content or its Markdown outputs. The full-shell 404 keeps its existing navigation.

**Page transitions:** Mobile navigation waits for the drawer/overlay to close before the existing 300ms 2D slide; route order determines direction. Reduced motion skips sliding and drawer motion. Desktop animation selection stays unchanged. Optional engine regression: `npx playwright install webkit`, then `npm run test:motion:webkit`; see the [test strategy](TEST-STRATEGY.md#test-strategy-en) for lifecycle and emulation limits.

**Accessibility baseline:** the existing Resume CTA palette and some existing sidebar text/link colors have light-theme contrast/distinguishability findings. They are preserved by the requested design constraint. The axe regression test scans and records these inherited findings against the actual source shell/CTA; unexpected findings still fail. The CTA baseline is measured on the theme surface because the hero image makes its original contrast inconclusive. This is not a claim of full WCAG conformance; correcting these colors requires a separate design change.

**MCP:** This portfolio does not declare a product API or tool service. The [Smithery `github` entry](https://smithery.ai/servers/GitHub), whose homepage is github.com, integrates with the GitHub platform; it is not evidence of a service owned by this portfolio. The audit's exact registry ID and matching method were not supplied, so the mechanism behind a possible incorrect match cannot be confirmed. [MCP 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) requires a POST/JSON-RPC runtime; static JSON is not a handshake. The current revision uses [server/discover](https://modelcontextprotocol.io/specification/2026-07-28/server/discover) and per-request metadata; `initialize` belongs to earlier revisions. The reviewed transport/discovery sections do not require `/.well-known/mcp`. Adding a file at that audit path does not create an MCP service. Pages cannot run the server without external infrastructure; no fake manifest is added.

```powershell
npm ci
npx playwright install chromium
npm run build
npm run verify -- --local --artifact --all --output=verification-local.json
npm run verify -- https://ferhattufekci.github.io --all --output=verification-production.json
```

Each verification run generates fresh UUID root and nested paths absent from the public inventory, then GETs the homepage and those paths with both Accept values. It records status, final URL, Content-Type, Vary and body evidence. Network, HTTP and content/format errors are distinct; an HTML fallback with status 200 is not valid JSON. Unsupported platform capabilities remain in `limitations`, do not count as passed capabilities and do not permanently break normal CI. A local server cannot prove the real Pages header behavior; inspect the post-deployment report together with the Actions commit.

The duplicate implementation note was removed after its maintenance information was moved into this guide. The test strategy, verification/ads/crawler files, older font formats referenced by CSS and separate CI check names are retained; absence of imports does not prove absence of external consumers. A new Is Agentic score requires a new Ora scan.

Format references: [llms.txt proposal](https://llmstxt.org/), [GitHub Pages custom 404](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-custom-404-page-for-your-github-pages-site). Risk coverage, the category decision table, FIRST and BDD are documented in the [Test strategy](TEST-STRATEGY.md#test-strategy-en).

### Blog — Medium Otomatik Senkronizasyonu

Makaleler, GitHub Actions aracılığıyla her 6 saatte bir Medium'dan otomatik olarak çekilir.

**Nasıl çalışır:**
1. `fetch-medium.js`, `https://medium.com/feed/@ferhattufekci` adresini okur
2. Kategori, RSS tag'lerinden otomatik tespit edilir (`systems` / `test` / `software`)
3. Önce yazının mevcut dil bilgisi kullanılır; yoksa `js/medium-language.js`, başlık ve içerikteki Türkçe/İngilizce sözcükleri değerlendirir. Senkronizasyon, tarayıcı yedeği, rozet ve dil filtresi aynı çözümleyiciyi kullanır.

Sağlayıcı/rıza yönetimi ayarları site sahibinin kararıdır.

**Platform sınırları:** GitHub Pages aynı URL'nin gövdesini ve Content-Type'ını Accept'e göre değiştiren uygulama kodu çalıştırmaz; [özel MIME ayarı da sunmaz](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site#mime-types-on-github-pages). `/index.md` faydalı bir alternatiftir; ana sayfada Markdown müzakeresi değildir. `/404.html`, olmayan kök/iç içe yollarda açıklamalı HTML ve gerçek 404 sağlar; Markdown hata yanıtı sağlamaz. Hash sunucuya gitmediği için `/#resumes` HTTP 200 içinde istemci 404 görünümüdür. `.md` MIME türü canlı yanıttan ölçülür.

**Ortak 404 ve kontroller:** `js/error-card.js`, iki hata görünümünün başlığını, mesajını ve kurtarma hedeflerini tanımlar. Üretici, sidebar/mobil başlık/gezinmeyi `scripts/lib/not-found-document.mjs` ile `index.html` içinden çıkarır; `js/site-shell.js`, SPA/plugin bağımlılığı olmadan ortak menüyü ve ölçülen mobil başlık yüksekliğini yönetir. Statik 404 bağlantıları ve asset'leri kök tabanlıdır. Yönlendirme yapılmaz: olmayan yollar HTTP 404 ve `noindex`, geçersiz hash'ler HTTP 200 olarak kalır. About/Contact/Privacy sade belge düzenini korur. İki kurtarma bağlantısı, About Me Resume CTA'sını değiştirmeden kullanır.

Tema ve menü kontrolleri ortak `.icon-btn` kullanır: hover yalnız gerçek hover destekli hassas işaretçide uygulanır; basılı geri bildirim bırakılınca biter; klavye odağı `:focus-visible` ile görünür. Escape/klavyeyle kapatma menü odağını geri getirir; fare/dokunmayla kapatma odağı çalmaz. Azaltılmış hareket tercihi ikon döndürme/ölçeklemeyi kapatır. Nötr temel margin, güven sayfalarındaki tema düğmesini de hizalar.

**Güven sayfalarında gezinme:** About, Contact ve Privacy indekslenebilir kalır; sitemap/ajan rehberinde ve footer'da bağlantıları korunur. Başlıklarında yalnız “← Back to portfolio” (`/`, About Me'yi açar) ve sağa hizalanmış tema düğmesi bulunur. Footer'daki mevcut sayfa, `aria-current="page"` taşıyan tıklanamaz metindir; bağlantı listesi `scripts/lib/agent-documents.mjs` içindedir. İki başlık hedefi de en az 44px yüksekliğindedir. Gezinme Markdown'a aktarılmadığı için bu düzen içerikleri veya Markdown çıktılarını değiştirmez. Tam portföy kabuğundaki 404 mevcut gezinmesini korur.

**Sayfa geçişleri:** Mobilde mevcut 300ms 2D kayma, çekmece/örtü kapandıktan sonra başlar; yönü rota sırası belirler. Azaltılmış hareket tercihinde kayma ve çekmece hareketi kaldırılır. Masaüstü animasyon seçimi korunur. İsteğe bağlı motor regresyonu: `npx playwright install webkit`, ardından `npm run test:motion:webkit`; yaşam döngüsü ve emülasyon sınırları [test stratejisindedir](TEST-STRATEGY.md#test-strategy-tr).

**Erişilebilirlik başlangıç durumu:** mevcut Resume CTA paleti ile bazı mevcut sidebar metin/bağlantı renklerinde açık temada kontrast/ayırt edilebilirlik bulguları vardır. İstenen tasarım kısıtı nedeniyle korunmuştur. axe regresyon testi bunları gerçek kaynak kabuk/CTA ile karşılaştırıp kaydeder; beklenmeyen bulgular testi başarısız yapar. Hero görseli özgün kontrast ölçümünü belirsiz kıldığı için CTA başlangıç ölçümü tema yüzeyinde yapılır. Tam WCAG uygunluğu iddia edilmez; bu renklerin düzeltilmesi ayrı bir tasarım değişikliğidir.

**MCP:** Bu portföy ürün API'si veya tool servisi ilan etmez. [Smithery `github` kaydı](https://smithery.ai/servers/GitHub), ana sayfası github.com olan GitHub platformu entegrasyonudur; portföyün servisi olduğuna kanıt değildir. Denetimin tam registry kimliği/eşleştirme yöntemi paylaşılmadığından yanlış eşleştirmenin mekanizması doğrulanamaz. [MCP 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) POST/JSON-RPC çalışma zamanı gerektirir; statik JSON handshake değildir. Güncel sürümde [server/discover](https://modelcontextprotocol.io/specification/2026-07-28/server/discover) ve istek başına metadata vardır; `initialize` önceki sürümlere aittir. İncelenen transport/discovery bölümleri `/.well-known/mcp` zorunluluğu tanımlamaz. Bu audit yoluna dosya eklemek bir MCP servisi oluşturmaz. Pages üzerinde harici altyapısız sunucu kurulmaz; sahte manifest eklenmez.

```powershell
npm ci
npx playwright install chromium
npm run build
npm run verify -- --local --artifact --all --output=verification-local.json
npm run verify -- https://ferhattufekci.github.io --all --output=verification-production.json
```

Doğrulayıcı her koşuda public envanterde bulunmayan yeni UUID kök/iç içe yollar üretir; ana sayfayı ve bu yolları iki Accept değeriyle GET üzerinden ölçer. Durum, final URL, Content-Type, Vary ve gövde kanıtı kaydedilir. Ağ, HTTP ve içerik/biçim hataları ayrıdır; 200 HTML fallback geçerli JSON sayılmaz. İmkânsız platform beklentileri `limitations` içinde kalır, geçmiş kontrol sayılmaz ve normal CI'ı sürekli kırmaz. Yerel sunucu gerçek Pages header davranışını kanıtlamaz; yayın sonrası rapor ve Actions commit'i birlikte kontrol edilir.

Temizlikte bu rehbere taşınan mükerrer uygulama notu kaldırılmıştır. Test stratejisi, doğrulama/ads/crawler dosyaları, CSS tarafından kullanılan eski font formatları ve ayrı CI kontrol adları korunur; import edilmemeleri dış kullanımlarının olmadığı anlamına gelmez. Yeni Is Agentic puanı ancak yeni Ora taramasıyla bilinebilir.

Biçim kaynakları: [llms.txt önerisi](https://llmstxt.org/), [GitHub Pages özel 404](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-custom-404-page-for-your-github-pages-site). Riskler, kategori karar tablosu, FIRST ve BDD kapsamı [Test stratejisi](TEST-STRATEGY.md#test-strategy-tr) belgesindedir.
